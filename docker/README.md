Docker image
============

The `Dockerfile` creates an image with all system, R and Python packages needed to create the usage statistics reports.
The image contains only these dependencies, not the scripts of this repository.

Getting the image
-----------------

The image is published as [ghcr.io/seqan/usage-plots](https://github.com/orgs/seqan/packages/container/package/usage-plots):

```console
$ docker pull ghcr.io/seqan/usage-plots:latest
```

Running the scripts
-------------------

From the root of a checkout, mount the repository and pass on the GitHub token (see [scripts/README.md](../scripts/README.md#github-token)).
The container runs as user `jenkins`, which needs write access to the directory the output is created in.

```console
$ docker run --rm -it -e GITHUB_PAT -v "$PWD":/usage_plots -w /usage_plots ghcr.io/seqan/usage-plots:latest
```

This opens a shell in the container:

```console
$ mkdir -p local/report && cd local/report
$ ../../scripts/run.sh ../../example/seqan-example.log
```

Building the image
------------------

The upload is not automated by CI yet; a new image has to be built and pushed manually.

The `Dockerfile` copies the requirement files from `scripts/config` via an additional build context.
`compose.yaml` defines this context, so build with `docker compose` instead of a plain `docker build`:

```console
$ docker compose -f docker/compose.yaml build
$ docker push ghcr.io/seqan/usage-plots:latest
```

Base image
----------

The `Dockerfile` uses a Jenkins base image because the reports are generated by a Jenkins cron job.
The scripts do not depend on it.
To use a different base, change `FROM` and, if the new base has no `jenkins` user, `ARG user` in the `Dockerfile`.
